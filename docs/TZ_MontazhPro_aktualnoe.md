## 1. Назначение и цели

Система принимает текстовые (или файловые) отчёты монтажников, распознаёт работы через локальную LLM (Ollama), сопоставляет их с прайс-листом и алиасами, считает ЗП и дописывает результат в месячную книгу Excel SE Луховицы. Дополнительно сохраняет разбор в локальную SQLite.

**Цели:**

- сократить ручной ввод в Excel и ошибки сопоставления работ;
- дать оператору предпросмотр, правку JSON и привязку нераспознанных работ к прайсу через алиасы;
- вести месячные книги с понятными именами таблиц `ГГГГ-ММ` в UI;
- работать локально (CPU Ollama), без облачных LLM.

## 2. Область применения

Внутренний инструмент учёта работ монтажников (сеть/ТВ, SE Луховицы). Пользователь — оператор/мастер. Интеграции с 1С и внешними ботами в текущий контур не входят.

## 3. Термины

| Термин | Значение |
|--------|----------|
| Таблица / книга месяца | Файл Excel одного месяца; в UI — метка `ГГГГ-ММ` (например `2026-10`) |
| Активная таблица | Книга для скачивания и индикации в настройках/отчёте |
| Алиас | Синоним из текста отчёта → официальное имя позиции прайса |
| Проблемная работа | Не сопоставлена с прайсом; красная в предпросмотре, в итог не входит |
| Бригада | Несколько ФИО в одном блоке; работы один раз, ЗП делится поровну |

## 4. Архитектура и стек

- Backend: FastAPI (`web/main.py`), порт 8000  
- Frontend: `web/static` (HTML/CSS/JS)  
- Ядро: `core/` (parser, pricing, excel_writer, workbook_factory, report_db, model_settings)  
- LLM: Ollama, по умолчанию `qwen2.5:3b` (переопределение в Настройках)  
- Данные: JSON-кэши, Excel в `data/workbooks/`, SQLite `data/reports.db`  
- Запуск: `python run_web.py` → http://127.0.0.1:8000  

## 5. Функциональные требования

### 5.1. Вкладка «Отчёт»

- Выбор таблицы Excel (`ГГГГ-ММ`) **перед** датой; при смене — активация и подстройка даты под месяц  
- Дата отчёта → дневной лист `01…31` и месяц книги при записи  
- Загрузка: файл / буфер / текст; опциональная доп. инструкция для ИИ  
- «Разобрать через ИИ» → предпросмотр и JSON  
- Проблемные работы: **выбор из прайс-листа** → алиас (`POST /api/aliases/link`) → автопересчёт (без «Добавить в прайс»)  
- Ручная правка JSON → «Пересчитать по прайсу»  
- «Сохранить в БД» (SQLite) и «Формировать отчёт» (Excel, с защитой от дублей)  
- Подсказка явно указывает, куда попадёт отчёт  

### 5.2. Прайс / Алиасы

- Прайс: CRUD → `data/price_list.json`  
- Алиасы: official + synonyms → `data/job_aliases.json`; автопополнение с вкладки «Отчёт»  

### 5.3. Настройки

- Активная таблица отображается как `ГГГГ-ММ`  
- Создать новую таблицу  
- **Заполнить или изменить таблицу:** список месяцев, активной сделать, изменить/дозаполнить, скачать, обновить список (синхрон с «Отчётом»)  
- Сотрудники и модель Ollama  

### 5.4. Лог Excel / Инструкция

- Лог записей активной книги  
- Встроенная справка; §3 — ручное исправление некорректно распознанных работ  

## 6. Пайплайн

1. Предобработка объёмов/адресов  
2. Ollama → JSON `workers[]`  
3. Валидация, бригады, reconcile объёмов  
4. Матчинг: алиас → точное имя → нечёткое (≥ 0.72)  
5. Расчёт ЗП; ненайденные в итог не входят  
6. Excel: числовые тариф/ЗП из UI-расчёта  

## 7. Книги Excel и именование

| Аспект | Правило |
|--------|---------|
| Метка в UI | Только `ГГГГ-ММ` |
| Файл на диске | `data/workbooks/SE_Lukhovitsy_ГГГГ-ММ.xlsx` |
| Куда пишется отчёт | Книга месяца **даты отчёта**, лист = день |
| Активная таблица | Скачивание/лог; выбор на «Отчёт» и в «Настройках» |
| Автосоздание | Нет файла → из шаблона + активация |
| Дубликаты | Дата + хэш текста |

## 9. Изменения 13.10.2026

1. Проблемные работы: выбор из прайса → алиас + пересчёт  
2. Инструкция §3: ручное исправление через JSON  
3. Выбор таблицы на «Отчёт» (перед датой); блок «Заполнить или изменить» в Настройках восстановлен и синхронизирован  
4. Отображение таблиц только как `ГГГГ-ММ`  

## 10. Критерии приёмки

1. Типовой отчёт разбирается с корректными суммами  
2. Выбор из прайса создаёт алиас и снимает «красноту» после пересчёта  
3. Правка JSON + пересчёт без повторного вызова ИИ  
4. Excel пишется в нужный месяц/день; дубликат не создаётся  
5. UI показывает `ГГГГ-ММ`; выбор на «Отчёт» и в «Настройках» согласован  
6. «Сохранить в БД» пишет читаемые строки в `reports.db`  
7. Инструкция содержит §3 про ручное исправление  

## 11. Вне скоупа

Синхронизация прайса Excel↔JSON; принудительная запись в «активный» месяц при другой дате; дедуп БД; 1С/VK-боты; Flet как основной UI.
