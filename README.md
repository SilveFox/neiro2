# МонтажПро (Neiro)

Веб-приложение разбирает текстовые отчёты монтажников через локальную нейросеть (Ollama), сопоставляет работы с прайсом, считает заработную плату и **дописывает** результат в месячную книгу Excel SE Луховицы.

Интерфейс: **http://127.0.0.1:8000** (вкладки Отчёт, Прайс, Алиасы работ, Настройки, Лог Excel, Инструкция).

## Как это работает

```
Текст / файл отчёта
  → предобработка объёмов (число до или после названия)
  → Ollama (qwen2.5:3b, CPU) → JSON workers[]
  → валидация, бригады, коррекция объёмов
  → расчёт по прайсу и алиасам
  → предпросмотр в таблице
  → (опционально) сохранение в SQLite — «Сохранить в БД»
  → запись в Excel месяца по дате отчёта
```

JSON отчёта в Excel **не пишется** автоматически — живёт в интерфейсе до «Формировать отчёт». Отдельно можно сохранить разбор и расчёт в **локальную БД** (кнопка «Сохранить в БД»).

## Требования

- Python 3.12+
- Запущенная **Ollama** с моделью `qwen2.5:3b` (`MODEL_NAME` в `core/config.py`; ориентир для CPU без GPU; на слабом CPU — `qwen2.5:1.5b`, при наличии GPU можно `qwen2.5:7b`)
- Шаблон Excel: `docs/SE_Lukhovitsy_iyun.xlsx`

```bash
pip install -r requirements.txt
```

Зависимости: FastAPI, Uvicorn, Pydantic, openpyxl, requests, python-multipart, flet (прототип).

## Запуск

```bash
python run_web.py
```

или `run_web.bat`. Откройте http://127.0.0.1:8000

Типовой сценарий:

1. Укажите **дату отчёта** (по ней выбирается месяц Excel и дневной лист 01…31).
2. Вставьте текст, файл (.txt, .docx, .xlsx, .csv) или буфер обмена.
3. **Разобрать через ИИ** → проверьте предпросмотр (красные строки — нет в прайсе).
4. При необходимости поправьте JSON и **Пересчитать по прайсу**.
5. При необходимости **Сохранить в БД** — архив отчёта с читаемыми ФИО и работами (не заменяет Excel).
6. **Формировать отчёт** — дозапись в книгу нужного месяца.

На вкладке **Настройки**: блок «Создать новую таблицу» (пустой месяц Excel) и «Заполнить или изменить таблицу» (активировать, скачать, дозаполнить через «Отчёт»). UI адаптирован под узкие экраны (меню-бургер ≤980px).

Если файла месяца нет, он **создаётся из шаблона и делается активным**. Запись идёт в `SE_Lukhovitsy_ГГГГ-ММ.xlsx` по дате отчёта, а не обязательно в ранее выбранный «активный» месяц.

Flet-прототип того же пайплайна: `python app.py`.

|------|------------|

| `pricing.py` | Прайс, алиасы, нечёткий поиск, `amount` / `total` / `per_person` / `grand_total` |
| `excel_writer.py` | Дозапись блока на дневной лист: тариф/ЗП числами из расчёта UI, K:L «наработка» |
| `workbook_factory.py` | Создание/активация месяца, `ensure_month_workbook` по дате отчёта |
| `report_db.py` | Сохранение отчёта в SQLite: заголовок, workers, jobs (читаемые строки) |

| `pipeline.py` | Программный вызов parse → calc → excel |

### Парсер

- Объём в начале строки (`3 выкладки…`, `19 сварок 1-7`) или в конце (`… 30 м`).
- Спецификации в названии не считаются объёмом: `1-7`, `24/500 мм`, `0.3 кг`.
- Заголовки заявок и адреса (`Калинина 49 бр`) не разбираются как работы.
- После ИИ объёмы сверяются с исходными строками (`reconcile_volumes_from_source`).

### Прайс и алиасы

Порядок матчинга: синоним → точное имя → нечёткое (порог ≥ 0.72). Тип услуги «Общее» в прайсе подходит к Интернет/ТВ. Словарь: `data/job_aliases.json`. Редактирование — вкладка **Алиасы** (поиск по названию и синонимам). Прайс runtime: `data/price_list.json` (вкладка **Прайс**).

### Итоги

- Строка: `объём × тариф`.
- Блок: `total`; на человека: `total / N`.
- Отчёт: `grand_total` (в предпросмотре «Итого»).
- В Excel: H = G×E, I = H/N, сумма блока SUM(H), справа K:L наработка по ФИО.

Ненайденные в прайсе работы в денежные итоги не входят.

### Excel

Шаблон: `docs/SE_Lukhovitsy_iyun.xlsx`

| Лист | Назначение |
|------|------------|
| **Данные** | Прайс: B — имя, C — цена, E — единица (VLOOKUP) |
| **Расчет** | Месячная сводка |
| **01…31** | Дневные блоки работ |
| **Шаблон** | Образец пустого дня |

Файлы: `data/workbooks/SE_Lukhovitsy_YYYY-MM.xlsx`, лог дублей `*.written.json`, указатель активной книги `data/active_workbook.json`.  
Дубликат: `report_date` + хэш текста. Бригада — один блок, работы один раз, ЗП делится поровну (`I = H/N`).

**Важно:** при записи в Excel тариф и ЗП сохраняются **числами из того же расчёта, что в предпросмотре** (JSON-прайс). Так файл сразу открывается с суммами: openpyxl при сохранении сбрасывает кэш формул, и «живые» VLOOKUP выглядели пустыми. Прайс на листе «Данные» и `price_list.json` лучше держать согласованными.

### Сохранение в БД (SQLite)

Отдельный шаг от Excel: кнопка **«Сохранить в БД»** в блоке «JSON от нейросети» (рядом с «Пересчитать по прайсу»).

- Файл: `data/reports.db` (`REPORTS_DB` в `config.py`), в git не входит.
- Берётся текущий JSON из редактора + расчёт по прайсу (если предпросмотра нет — пересчёт выполняется автоматически).
- Пишутся **читаемые** поля, не только JSON:
  - `reports` — дата, `workers_names`, `jobs_summary`, итог, модель, время;
  - `report_workers` — ФИО/бригада, headcount, total, per_person;
  - `report_jobs` — сотрудник, название работы (из прайса при матче), объём, ед., тариф, сумма.
- Полные JSON отчёта и расчёта также хранятся в колонках `report_json` / `calculation_json` для восстановления.
- Запись в БД **не проверяет дубликаты** (в отличие от Excel) — каждое нажатие создаёт новую строку.

Пример просмотра:

```sql
SELECT worker_name, task_name, volume, unit, unit_price, amount
FROM report_jobs
ORDER BY id DESC;
```
